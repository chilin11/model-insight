# 快速写一篇文章

本站固定域名、AI 投稿与站长批量发布命令见 [固定发稿方法](PUBLISHING.md)。

## 你自己写

1. 打开 `https://你的域名/admin`，输入 `ADMIN_TOKEN` 登录。密钥读取方式见部署说明，不要把管理员密钥交给 AI。
2. 点 **写新文章**，写标题、摘要、分类、模型和「先看结论」。
3. 正文使用 Markdown，点 **保存草稿**（或 Cmd/Ctrl + S）。保存成功才写入服务器，公开页面看不到草稿。
4. 按需上传图片，填写替代文字、说明和出处。可以复制上传后的图片地址，在正文写 `![图片说明](/media/文件名.png)`。图片上传成功不等于文章已保存。
5. 添加至少一个原始来源，填写名称、HTTP(S) 原文链接和来源类型；核对发布日期与资料核验日期。事件日期放在「事件时间与资料口径」，不要混成文章发布日期。
6. 点 **预览**，检查标题、正文、图表和来源，再点 **发布文章**。
7. 刷新公开网站即可看到，无须重新构建。发布后可保存修改、撤回为草稿，也可设为首页头条。

发布至少需要：标题、摘要、正文或结构化段落、一个有效来源、发布日期及核验日期。未填写完整可以先存草稿；不合法链接、日期等仍会被拒绝。保存失败时编辑内容留在当前窗口，不会显示为成功。

## 让 AI 写

把 [API 文档](API.md) 和 `examples/ai-draft.json` 交给你的服务端工作流，配置独立 `API_TOKEN`。不需要指定 AI 厂商：脚本、智能体或自动化工具都可以 POST JSON。

工作流：**搜集原始资料 → AI 整理成 JSON → 调用草稿接口 → 你在后台刷新列表 → 核验与修改 → 手动发布**。

AI 必须为每篇文章生成唯一 `id`，只用小写英文字母、数字与连字符，最长 80 字符。重复 ID 返回 409，不会覆盖旧稿。`status` 只能是 `draft`。本平台接收成稿，不负责调用模型或自动编造来源。

## 编辑器工具栏

正文上方的工具栏可以插入：二级/三级标题、加粗（⌘/Ctrl+B）、斜体（⌘/Ctrl+I）、删除线、链接（⌘/Ctrl+K）、引用、提示框、行内代码（⌘/Ctrl+E）、代码块、列表、表格、脚注和分隔线。选中文字后再点按钮，会包住选中内容。

- **图片**：点工具栏图片按钮，或直接**粘贴截图 / 拖入图片**到正文，会自动上传并在光标处插入 `![描述](/media/…)`。请把「请填写图片描述」改成真实描述。
- **编写 / 分屏 / 效果**：分屏时左边写、右边实时显示读者看到的效果（手机上没有分屏）。
- 底部显示字数和预计阅读时间；「阅读分钟」旁的「估算」按钮可一键填入。
- 浏览器原生撤销（⌘/Ctrl+Z）可撤销工具栏插入。

## 互动、分享与删除

- 每篇文章底部有读者评论。评论**先进入「评论审核」**（后台顶部，红色数字为待审核数），点「通过并公开」后才显示；可撤下、移回待审或永久删除。
- 「互动与分享」里可勾选**关闭本文评论**：已公开评论保留，读者不能再提交。
- 已发布文章可「复制分享链接」，格式为 `https://你的域名/a/文章ID`。这个链接带标题、摘要和配图信息，微信、微博、X、Telegram 等平台可显示预览卡片。读者端「分享」按钮提供复制链接、系统分享、微信二维码、微博、X、Telegram 和邮件。
- 网站提供 RSS：`https://你的域名/rss.xml`，按发布日期列出最新 30 篇。
- 草稿可以「删除草稿」（不可撤销）；已发布文章需先撤回为草稿才能删除，避免误删公开内容。

## Markdown 常用写法

```md
## 发生了什么

这里是正文，**重点加粗**。厂商自测要明确说明。

[官方原文](https://example.com/announcement)

| 项目 | 数据 | 口径 |
| --- | --- | --- |
| 示例 | 需要核验 | 不同测试版本不混排 |

![图片替代文字](/media/上传后的文件名.png "图片出处与说明")

> 引用原文，用于转述官方或社区说法，后面注明出处。

> [!WARNING]
> 提示框：以下成绩为厂商自测。可用 NOTE（说明）、TIP（提示）、IMPORTANT（重点）、WARNING（注意）、CAUTION（风险），也可写中文 [!注意]。

官方称成功率提升 11 个百分点[^1]。

```python
print("代码块写上语言名即可高亮：python、ts、js、go、bash、json、yaml、sql、diff 等")
```

- [x] 已核验官方原文

[^1]: 来源：[官方公告](https://example.com/news)，2026-10-17。
```

代码块右上角有「复制」按钮；图片引号里的文字显示为图注；脚注会在文末汇总为「注释与来源」，点击编号在文内跳转。

不支持原始 HTML、脚本和 SVG 上传。外部图片只允许 HTTPS，且会直接请求图片所在站点；优先上传你有权使用的真实截图。

## 编辑现在的 9 篇文章

从文章列表打开即可修改标题、摘要、来源等信息。原有分节正文、表格和数据图完整保留在 **结构化正文、原有表格与图表**，不需要迁移就能继续展示。高级编辑可修改里面的 JSON，保持 `heading`、`text`、`table`、`chart` 和 `sourceNumbers` 结构；来源编号从 1 开始。

Markdown 正文会显示在原有结构化段落之前。不要同时粘贴整篇旧文到 Markdown，否则会重复展示。修改结构化正文出错时不会自动覆盖服务器内容。

## 冲突和未保存内容

- 切换文章、退出或离开页面会提醒未保存修改；浏览器本身的关闭提醒取决于浏览器支持与用户交互。
- 两个窗口同时编辑同一篇时，后保存的一方会收到版本冲突，不静默覆盖。
- 遇到冲突：点 **导出当前稿** 保存本地副本 → **重新读取列表** → 重新打开服务器版本 → 合并修改后保存。
- 「导出当前稿」保留当前文章对象以及结构化正文原始文本，是人工合并副本，不是全站备份。全站数据备份见部署文档。
- 目前没有自动保存；看到「草稿已保存」或「已发布」后才可放心关闭。预览本身不会保存。

## 采编检查

官方资料、厂商自报成绩、独立评测、社区个体体验和编辑观点分开写。写清模型版本、测试环境与日期。少数回复不代表社区共识；没有实测不要写成本站测评。引用社区内容保留原帖、作者与楼层，概括转述不要冒充逐字引文。
